# ТЗ: удаление фото админом прямо из галереи

## Зачем

Брак (неудачные генерации из ComfyUI) сейчас удаляется только в админке на `secure.artai.win`. Нужно, чтобы админ
мог удалить фото сразу, пока смотрит галерею на сайте: иконка корзины рядом с сердечком.

Решено: удаление сразу и насовсем, без мягкого удаления и восстановления. Брак проще сгенерировать заново.

## Что есть сейчас

- Фронт не отличает админа от обычного пользователя: `/me` отдаёт только `id`, `email`, `dateJoined`
  (`MeSerializer` в `accounts/api/serializers.py` бэкенда).
- Удалить фото через API нельзя. Удаление есть только в админке: `PhotoService.delete`.
- Сердечко находится в `src/components/PhotoGrid.vue`. Сетку используют галерея, главная и избранное.
- `me` (текущий пользователь) загружается в `src/entry-client.ts` после гидрации. При SSR и при первом рендере
  на клиенте пользователь анонимный.

## Бэкенд (репозиторий `image-gallery`)

### 1. Признак админа в `/me`

- Добавить в ответ `GET /me` поле `isAdmin: boolean` = `user.is_staff`.
- Изменение не ломает API: старые клиенты новое поле просто игнорируют.

### 2. `DELETE /photos/{photo_id}`

- `photo_id` — публичный id фото (поле `id` в ответах API), не pk.
- Доступ только для `is_staff`, через `rest_framework.permissions.IsAdminUser`.
- Удаление через `PhotoService.delete(Photo.objects.filter(public_id=photo_id))`. Ничего дополнительно делать
  не нужно, всё уже работает само:
  - файлы из media удаляет сигнал `post_delete` (`gallery/signals.py`), если на них не ссылаются другие фото;
  - обложка галереи сбрасывается на случайное фото (FK `SET_NULL`);
  - записи в избранном удаляются каскадом.
- Ответы:

| Код | Когда |
| --- | --- |
| 204 | Удалено |
| 401 | Нет токена или токен истёк |
| 403 | Пользователь не админ |
| 404 | Фото с таким id нет: уже удалено или id перевыпущен |

- Описать в OpenAPI (`extend_schema`), как соседние эндпоинты.

### 3. Тесты

- `/me` отдаёт `isAdmin: true` для staff и `false` для обычного пользователя.
- `DELETE`: админ получает 204 и фото пропадает из БД; обычный пользователь получает 403, аноним 401,
  несуществующий id даёт 404.

Сообщение для коммита: `feat(api): let admins delete photos via api and expose isAdmin in /me`.

## Фронт (этот репозиторий)

### 1. API (`src/api.ts`)

- `Me` получает поле `isAdmin: boolean`.
- `deletePhoto(id)` отправляет `DELETE /photos/{id}` через `request()`, так же как `setFavorite`.

### 2. Иконка корзины (`src/components/PhotoGrid.vue`)

- Кнопка рендерится только при `me?.isAdmin`. На сервере и при первом рендере на клиенте `me` равен `null`,
  поэтому расхождения при гидрации не будет: кнопка появится, когда загрузится `/me`.
- Кнопка стоит рядом с сердечком (слева от него) и выглядит так же: круглая, полупрозрачный фон. Видна при
  наведении, на тач-устройствах видна всегда. При наведении на саму кнопку она подсвечивается красным (`error`).
- Перед удалением нужно подтверждение: `confirm()` с текстом из i18n. Случайный клик ничего не удаляет.
- Пока идёт запрос, кнопка заблокирована, повторный клик игнорируется.
- Успех (204) и 404 (фото уже нет): фото пропадает из сетки, `total` уменьшается на 1, перезагрузки страницы нет.
- Другая ошибка: фото остаётся, показывается ошибка (`errorMessage()` из `i18n.ts`). 401 обрабатывается
  как в `useFavorite`.
- Корзина появится везде, где используется `PhotoGrid` (галерея, главная, избранное). Это нормально.

Как убирать фото из списка: добавить в `useInfiniteList` метод `remove(id)`, который убирает элемент из `items`
и уменьшает `total`. `PhotoGrid` вызывает его через событие `delete` или через проп. Мутировать проп `items`
напрямую не нужно.

### 3. i18n (`src/locales/en.json`, `ru.json`)

| Ключ | en | ru |
| --- | --- | --- |
| `photo.delete` | Delete photo | Удалить фото |
| `photo.deleteConfirm` | Delete this photo for good? | Удалить фото насовсем? |

### 4. Тесты (vitest)

- Обычный пользователь и аноним корзину не видят, админ видит.
- После подтверждения вызывается `deletePhoto` и фото пропадает из списка. Если в `confirm()` нажать «Отмена»,
  запроса нет.

Сообщение для коммита: `feat(gallery): let admins delete photos from the grid`.

## Не входит в задачу

- Корзина внутри лайтбокса (PhotoSwipe). При удалении пришлось бы пересчитывать индексы слайдов. Можно
  сделать следующим шагом.
- Массовое удаление нескольких фото.
- Удаление галереи целиком.

## Порядок выкатки

1. Бэкенд: мерж в `main`, CI выпускает релиз, затем `deploy/deploy.sh <sha>`.
2. Фронт: мерж, затем деплой. Если выкатить фронт раньше бэкенда, ничего не сломается: `isAdmin` не придёт,
   и корзина просто не появится.

## Готово, когда

- [ ] Под админом в галерее рядом с сердечком видна корзина, у обычного пользователя и гостя её нет.
- [ ] Клик, подтверждение: фото пропадает из сетки, после перезагрузки его тоже нет, файлы удалены с диска.
- [ ] Прямой запрос `DELETE /photos/{id}` с токеном обычного пользователя даёт 403.
- [ ] Тесты бэкенда и фронта зелёные.
